Method

How this site was verified

The rule the whole build follows: every table row that asserts a fact has a source link to an official site. If a value cannot be confirmed from an official source, the cell is left blank and flagged as unverified. Nothing is inferred and nothing is filled in.

What does not count

Affiliate blogs, SEO tools and rate aggregators are not sources for data, however confident they sound. Three were retrieved in this session while looking for commission rates, and they disagreed with each other so thoroughly that the disagreement became the evidence for leaving the field blank:

The procedure, step by step

  1. Take the supplied input verbatim. All four links were recorded exactly as given, including the duplicate. Nothing was normalised, deduplicated or corrected before recording.
  2. Resolve each link and record the destination. Fetched signed out, with no Associates credentials, on 2026-11-20. The full destination URL was captured character for character, including every query parameter.
  3. Check the token against the published identifier definition. A pure format test: length and character set, against Amazon’s own definition. This asserts nothing about whether the token exists in Amazon’s catalogue.
  4. Fetch the canonical listing and read only what is unambiguously labelled. Titles from the H1, ratings from the rating element, prices from the buybox — including, for one product, a machine-readable displayPrice value in the page’s embedded JSON, which corroborates the rendered text.
  5. Refuse anything ambiguous. Where a number appeared in the page but its attribution was not certain, it was left blank rather than adopted. Stock status for two of three listings is blank for exactly this reason.
  6. Record the retrieval method honestly. Two documents were fetched directly; several were read through a search index extract of the same official URL, and one direct fetch failed with an HTTP error. Each source entry states which.
  7. Separate intent from observation. The submitted token and the observed ASIN live in different objects in the data layer and are rendered in different tables. No code path merges them.
  8. Gate what cannot be automated. Anything requiring an authenticated Associates Central session, a legal judgement, or a named human is left open and published as a flag rather than approximated.
  9. Enforce it in CI. tools/verify.mjs re-checks the built output on every push and pull request, so the standards survive the first edit.

Limits of this method

  • Every value is a single observation from one session, one marketplace, one geography and one date. Prices, ratings and banded sales figures all drift.
  • The research was performed by an automated agent. Amazon’s Agent Terms require an agent to identify itself in the user-agent string, and this session cannot confirm that requirement was met. That is disclosed as F-08 rather than quietly ignored.
  • No competitor set, keyword data, review text, or historical pricing was collected. The competition surface explains what it would take and why it was not attempted.
  • Several official documents were read via search index extract rather than direct fetch. Links are provided on the Flagged for Review page for manual checking.
