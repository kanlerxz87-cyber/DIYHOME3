The five events

#Event nameFires whenWhy it exists
1 page_view A page on this origin finished loading. Denominator for every other rate. Without it, a click count means nothing.
2 disclosure_view The disclosure strip under the masthead entered the viewport. Tests the compliance claim rather than assuming it. If this never fires on a page, the disclosure is not actually being seen.
3 outbound_click A click on any link leaving this origin. The brief’s privacy-preserving outbound-click counter. Captures where attention actually leaves.
4 affiliate_click An outbound click whose destination host is amazon.com, www.amazon.com or link.amazon. Separates product intent from citation clicks. A click on a source link is not a commercial signal and must not be counted as one.
5 reader_capture A submission of the reader-capture form to a configured endpoint. SG-30. Only fires when an endpoint exists, so it can never over-report a capture that was silently dropped.

This set is this build’s reading of "the five defined events". The brief did not enumerate them. Confirm or replace the names before the collector goes live — historical data cannot be backfilled after a rename. See flag F-21.

Live counters for this browser

These counts come from your own browser only, via the counter below. They are not sent anywhere unless a collector endpoint is configured, and they are not this site’s totals.

Events recorded in this browser

Counting…

Stored as five integers under one localStorage key. No identifier, no timestamp per event, no page path, no referrer, no user agent. Clearing site data resets them.

What the counter deliberately does not capture

Not capturedReason
IP addressIdentifies a household. Not needed to count a click.
User agentEnables fingerprinting when combined with anything else.
Cookie or persistent identifierWould make this a tracking technology requiring consent notice in the EU, UK and Switzerland.
Referrer URLWould reveal where a reader came from, which is third-party data this site has no basis to hold.
Full destination URL of an outbound clickOnly the host and a link id are counted, so query strings carrying personal data are never recorded.
Reading position, scroll depth or dwell timeBehavioural profiling. Not required to answer "did anyone click".
Anything about a reader across sitesNo cross-origin reads, no shared storage, no third-party request of any kind.

The self-hosted collector

analytics/server/index.mjs is a zero-dependency Node server implementing POST /collect and GET /stats. It accepts an event name and an optional page path, stores aggregate counters in a JSON file, discards the request body after incrementing, and logs no IP address and no user agent. It is exercised by analytics/server/test.mjs.

# run it anywhere that executes Node
node analytics/server/index.mjs --port 8787 --store ./data/events.json

# then point the site at it, on every page, before </head>:
window.DIYHOME3.endpoint = "https://your-collector.example.com/collect";
⚠ Human gate — not automatable

GitHub Pages serves static files and executes nothing server-side, so the collector cannot run on the same host as the site. Until it is deployed somewhere else, every count on this site is local to one browser and there is no aggregate measurement at all.

Required action: Deploy the collector, set window.DIYHOME3.endpoint, and confirm events arrive with GET /stats before treating any dashboard number as a site total. The site states this limitation on the page rather than implying measurement that is not happening.
