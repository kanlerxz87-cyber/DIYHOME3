Competition and category context

Dashboard

Scope limit, stated up front

A real competitive analysis needs the set of competing listings in a category, their prices, their ratings, their review velocity and their ad presence. None of that was collected, and collecting it would mean scraping Amazon search results at scale. What follows is category context derived only from what appeared on the three verified listing pages — including Amazon’s own "Customers who viewed this item also viewed" carousel, which is the one competitive signal legitimately available from a single page.

Adjacent listings surfaced by Amazon on each page

Each listing page rendered a "Customers who viewed this item also viewed" carousel. Those are Amazon-selected adjacencies, not a market survey, but they are the only competitor set observable from a verified single-page fetch. Irregularity in the adjacency data

The carousel rendered next to B0BSKQW2T2 included a key holder (B0B7RRGJCM), which is not a paper towel holder and not in the same leaf node. Amazon’s "also viewed" carousel is a behavioural recommendation, not a category listing, so it mixes in products that shoppers happened to view in the same session. It must not be read as a competitor set. This is recorded because treating carousel content as competitive intelligence is an easy and common mistake.

What a real competitive analysis would require

  • A defined competitor set per leaf node, not an Amazon recommendation carousel.
  • Price, rating and ratings-count history over time for each competitor, to see velocity rather than a snapshot.
  • Advertising presence, which is only observable from the search results page and changes per session.
  • Review velocity — the rate at which ratings accumulate, which needs repeated observation.
  • Sell-through signals beyond Amazon’s banded "bought in past month" figure.
⚠ Human gate — not automatable

None of the above can be built from a single static fetch, and building it by scraping search results at scale would sit badly against Amazon’s Agent Terms, which require an autonomous agent to identify itself and prohibit circumventing measures that control agent access.

Required action: If competitive intelligence is genuinely wanted, source it from the PA-API or Creators API under an enrolled Associates account, or from a licensed data provider, and record which. Do not scale up page scraping.
